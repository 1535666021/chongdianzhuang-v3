## 关键缺陷修正（2026-11-28 07:06 甲方裁定）
- 当前 `TagCloud` 的「全部(N)」用 `tags.reduce(sum count)`，而 region tags 是层级累计：一单会计入省/市/区县/乡镇多级，导致 9 单被加成 26。
- 必修：`全部(N)` 只能等于当前过滤后的订单数 `base.length`，不得等于各级 count 相加；TagCloud 需增加 `total` prop，`useTagCounts` 返回 `regionTotal=base.length`。
- 若区域层级树未完成，临时也要把层级 tags 按“累计标签”展示且标明不可相加；不得把 26 当订单总数。

## 层级口径修正（2026-11-28 07:08 甲方裁定）
- 不要省层级；最高一级就是市，例如安庆市。
- 结构固定为：市 → 区/县/县级市 → 乡镇/街道级中的乡镇；最细到乡镇，不再到村/路/小区。
- 总数必须对得上：全部=去重订单总数；每个市/区县/乡镇 count=该区域内去重订单数；子级 count 之和等于父级 count。

## 交互显示修正（2026-11-28 07:09 甲方裁定）
- 一级列表显示当前订单涉及的城市：如「安庆市（9）」「潜山市（n）」；全部总数=各城市去重订单之和，且必须等于已导入/当前列表总数。
- 点开安庆市：顶部显示「安庆市共 X 单」；下方按区/县/县级市分组，每组标题显示区名+数量（如宜秀区(2)、怀宁县(3)、潜山市若属安庆则按其规则），组下直接列出该组订单。
- 再点区县：显示「该区县共 X 单」，下按乡镇分组并列订单；返回路径清晰（返回市/返回全部）。
- 订单不得在不同区域重复计入；移动/导入后重算，所有计数实时同源。
